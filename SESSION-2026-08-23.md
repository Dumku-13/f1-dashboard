## 2. What was built

### Mobile (PR #1)

The finding that framed it: the app had **one** width-based media query in 823
lines of `globals.css` against **~2,800 inline `style={{}}` props** — and a media
query cannot reach an inline style. So every route *fit* a phone and rendered at
desktop density. Fitting and reading are different measurements; only the first
had ever been taken.

- `lib/breakpoint.ts` — one `matchMedia` store behind `useSyncExternalStore`.
- Phone type floor in `globals.css` via attribute selectors.
- `MobileTabBar` replaces the dock under 768px (the dock held 426px of content
  in a 351px rail and auto-hides on scroll — wrong for a live tower).
- `navRoutes.ts` — the 25-route map extracted so dock and tab bar share one list.
- `/live` tower reflowed to five columns on phone; `/standings` gets a sticky
  POS + DRIVER anchor.

Measured at 375px, text under 12px: `/live` 178→0, `/standings` 341→0,
`/dashboard` 56→0, `/follow` 31→0. Desktop re-measured unchanged.

## 3. The two findings worth carrying forward

**Track-map dots — root cause identified, not yet fixed at source.**
`/state` now has a `diag` block counting inbound frames per topic. It reports
`Position.z` **absent from `frames` entirely** while all ten other subscribed
topics arrived, with `position_errors: 0`. So F1 does not send the compressed
position topic to this client — it is not a decode failure. **Why is still
open and needs a live session.** The dots work meanwhile via OpenF1.

**Kalshi needs no API key — an earlier session's note was wrong.**
That note (chat log only, never in `HANDOFF.md`) said "needs credentials" after
testing `trading-api.kalshi.com`, which is the *order-placing* host. Market data
comes from `api.elections.kalshi.com`, public and unauthenticated. It also looked
unreachable because `curl` fails the TLS handshake against it at Windows
schannel level while `httpx` connects fine.

## 4. Traps that cost real time

Each is a `HANDOFF.md` invariant now; repeated here because they are the ones a
new session is most likely to walk back into.

- **React emits two serialisations of the same inline style.** SSR writes
  `font-size:11px`; a style touched through the CSSOM re-serialises as
  `font-size: 11px`. A rule for one form fixes about half the page.
- **Fractional font sizes are a real pattern here** — 31 declarations at
  9.5/10.5/11.5px. Integer-only rules miss all of them.
- **recharts' class is `.recharts-text`**, not `.recharts-cartesian-axis-tick`
  (a `<g>` two levels up). Size is an SVG presentation attribute, so any CSS
  rule wins — if the selector matches.
- **Kalshi prices live in `*_dollars` string fields.** The integer
  `last_price` / `yes_bid` fields are `null`, making an 8.0M-volume market look
  dead. Also: do not reuse the HTTP connection (`WinError 10054`).
- **`Number(null)` is `0`, not `NaN`.** A null coordinate survived a finite
  check and planted a car on the pit straight. Caught by a test.
- **The bridge reports `active: true` for a *finished* session.** The OpenF1
  position fallback fired every 4s poll forever and took a 404 each time until
  it was gated on `sessionIsLive`.
- **SVG text scales with its container.** Turn numbers at 7.5px read fine on a
  590px desktop map and ~6.4px on a 375px phone.

## 5. Merge order, and why it bit

All three branches touched `HANDOFF.md`; #1 and #3 both touched
`TimingTower.tsx` and `globals.css`. Merging #1 put #2 and #3 into conflict.

`TimingTower.tsx` had **10 conflict regions** — #1 added a `phone` mode, #3
added `expanded`, and they had to compose rather than one winning:

```
phone              -> PHONE_TOWER_GRID + full-width second line
desktop, expanded  -> TOWER_GRID + MINI-SECTORS
desktop, collapsed -> COLLAPSED_TOWER_GRID + S1/S2/S3
```

**Verifying that merge caught a regression that all three green PRs had missed:**
the turn numbers from #3 broke the zero-sub-12px guarantee from #1 on a phone.
Fixed by scaling them to 11px under 768px. Lesson for next time: after merging
branches that touch the same component, re-run the *other* branch's acceptance
measurement, not just the build.

## 6. Verification in this environment

Screenshots **fail outright** — the browser pane never composites. Two
consequences that shaped the work:

- Placement has to be checked numerically. `scripts/pit-lane.test.mjs` exists
  because "22 dots appear in the DOM" says nothing about *where* they were
  drawn. It caught three real bugs (queue doubling back on itself, an
  unreadable diagonal clump, and overlapping bubbles after a radius change).
- jiti cannot parse JSX, so pure logic that needs testing has to live in a
  `.ts` file — that is why `components/live/pitLane.ts` is split out of
  `TrackMap.tsx`.

Two new test scripts (**12 total**) and two fixtures:
`fixtures/openf1-location-zandvoort-2024.json`,
`fixtures/track-details-zandvoort-2024.json`.

Also: the dev server and backend both died several times mid-session, and the
browser tab crashed once. If the page looks broken, check both are actually up
before debugging the code. `/api/livetiming/track` is a slow cold fastf1 call —
the map renders empty until it returns.
